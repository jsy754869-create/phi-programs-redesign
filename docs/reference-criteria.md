# 레퍼런스 선정 기준 (초안, 2026-10-19)

각 섹션 정보의 성격 → 레퍼런스에서 찾을 **원리**(형태가 아니라 "무엇을 어떻게 처리하는가")를 정리한다.
레퍼런스는 도메인과 무관하게, 아래 질문에 답하는 처리를 찾는다.

## 0. 페이지 전체
- **성격**: 질문이 다른 6개 섹션이 이어지는 약 8,000px의 단일 스크롤. 다시 찾아가고 비교하는 행동이 일어난다.
- **찾을 원리**
  - G1. 긴 페이지에서 전체 구성과 현재 위치를 함께 알게 하되, 본문 몰입을 방해하지 않는 처리
  - G2. 섹션마다 정보 형태가 달라도 하나의 페이지로 읽히게 하는 처리

## 1. Hero
- **성격**: 원고를 고치지 않는 선언적 메시지(긴 문단 2개, 핵심은 문단 안에 있음) + 짧은 사실 데이터(라벨-값 5쌍).
- **찾을 원리**
  - H1. 페이지 제목(현재 위치)과 긴 본문 속 핵심 메시지가 역할을 나눠 둘 다 읽히게 하는 처리 (수정: 본문이 제목보다 먼저 → 역할 분담)
  - H2. 선언적 메시지와 라벨-값 데이터를 한 화면에서 서로 다른 종류로 구분하는 처리

## 2. 역량과 태도
- **성격**: 순서가 없는 동등한 개념 10개(5+5)가 두 그룹으로 나뉜다. 각 항목은 한글명, 영문명, 3~4문장 설명으로 이루어진다. 훑다가 관심 있는 것만 읽는다.
- **찾을 원리**
  - C1. 동등한 항목 여러 개를 단조롭지 않게 훑게 하면서도 위계를 만들지 않는 처리
  - C2. 같은 형식의 두 그룹을 다른 그룹으로 인식하게 하는 처리
  - C3. 한 항목에서 다른 섹션의 관련 항목으로 이어지는 연결을 보여주는 처리

## 3. 주요 수업
- **성격**: 동등한 수업 12개. 각 수업은 영문명, 한글명, 설명 문단, 상세 페이지(Course Profile) 링크로 이루어진다. 사용자는 이 목록을 비교하고 선택한다.
- **찾을 원리**
  - L1. 많은 항목을 길게 나열하지 않고 비교하며 훑게 하는 처리
  - L2. 목록의 요약에서 상세(외부 페이지)로 들어가는 진입점을 처리하는 방식

## 4. 배우는 방식
- **성격**
  - 프로그램 구조: 포함 관계(Course ⊃ Fundamental / Domain / Ritual)와 병렬 관계(Study / Workshop / Event)가 섞인 분류 체계. 유형마다 기간과 빈도라는 같은 속성을 가진다.
  - 핵심 수업 장치: 추상 개념(인지적 도제) 1개 + 짧은 항목 6개. 상세는 숨겨져 있다.
- **찾을 원리**
  - M1. 포함 관계와 병렬 관계가 섞인 구조를 한눈에 이해시키는 처리
  - M2. 여러 항목의 같은 속성(기간, 빈도)을 나란히 비교하게 하는 처리
  - M3. 접힌 상태에서도 항목의 의미가 짐작되게 하는 점진적 공개 처리

## 5. 1년의 흐름
- **성격**: 순차적인 시간 데이터(4개 기간, 날짜)와 기간별 설명, 방학 캠프 3개, 수료와 졸업의 정의. 주간 시간표는 한 단계 깊은 세부 정보다.
- **찾을 원리**
  - T1. 시간의 순서와 길이(비율)를 읽지 않고도 감지하게 하는 처리
  - T2. 개요와 세부(연간 → 주간)를 같은 맥락 안에서 깊이만 다르게 보여주는 처리

## 6. 졸업 이후와 지원
- **성격**: 짧은 약속 2개(그중 하나는 "검토 중" 각주가 붙은 미확정 정보) + 다음 시점(2기 지원 시작일) + 행동 유도. 페이지의 끝이다.
- **찾을 원리**
  - E1. 긴 페이지를 끝맺으면서 다음 행동을 자연스럽게 제시하는 처리
  - E2. 확정 정보와 미확정 정보를 신뢰를 잃지 않게 구분하는 처리
